## 真实 MySQL 与浏览器端到端

应用以最终 JAR 连接本机独立 MySQL 8.4.10，浏览器完成以下操作：

1. 获取 CSRF Token 并使用自建管理员登录；
2. 进入平台壳中的“临床研发管线”子 Tab；
3. 创建研究 `HD-UI-007`，页面自动刷新并展示后端返回的状态文案；
4. 进入“平台管理”，在线修改 `platform.display-name`；
5. 创建普通用户 `e2e.user2`；
6. 正常退出登录。

关键 HTTP 结果：登录 `200`、研究创建 `201`、配置更新 `200`、账号创建 `201`、退出 `200`。浏览器没有非预期控制台错误。

随后直接查询 MySQL，得到：

```text
MYSQL_VERSION=8.4.10
FLYWAY_ROWS=1
STUDY=HD-UI-007|ON_HOLD
SETTING=platform.display-name|E2E Research Platform 2|mysql-admin
USER=e2e.user2|USER|1
```

页面实测截图：[12-mvp-live-mysql.png](./screenshots/12-mvp-live-mysql.png)。

## 验证中修复的问题

- 登录页初始化 CSRF 与快速提交之间的竞态；
- `201` 空 JSON 响应导致前端解析异常；
- 异步表单在 `await` 后继续访问已失效的 `event.currentTarget`；
- 新版浏览器 `pattern` 正则模式下用户名连字符未转义。

## 尚未在本机执行的边界

本机没有可用 Docker Engine，因此没有在本机实际运行 `docker compose up` 或构建容器镜像；Dockerfile、Compose、Prometheus、告警和 GitHub Actions 已完成静态配置。首次云部署前必须由 CI 构建镜像并在预发布环境执行相同的健康检查与浏览器冒烟。
