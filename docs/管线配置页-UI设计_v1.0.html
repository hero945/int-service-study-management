设计说明 · 实体分离 + 引用

对应产品决策：Program / Project 为独立实体，Study 表通过外键引用；编辑一行不会隐式影响其他行。编号与页面标注一一对应。

1

双视图结构

默认「Study 明细」承载高频操作（查、加、改 Study）；「Program / Project 管理」承载低频实体维护。两个视图共享同一份实体数据，切换无刷新。

2

Project 引用列

Study 行的 Project 以引用 chip 呈现（业务编码），点击展开实体摘要浮层：适应症、TA、下挂 Study 数，可跳转管理视图。引用不是自由文本，从源头杜绝同名字段不一致。

3

行内编辑只碰 Study 自身字段

进入编辑态后，Source / Origin / Product / MOA / Program / Indication / TA 全部锁定（灰底 + 只读标记）——这些字段已上移至 Program / Project 实体。可编辑项只有：所属 Project（换绑）与 Phase Status。业务编码与实时计算的「项目状态」永远不可编辑。

4

重命名 = 影响面预览 + 显式确认

重命名 Program / Project 弹窗内先展示影响面（下挂 X 个 Project、Y 条 Study），勾选「我已了解」后才可提交，一次事务生效。业务编码不变，所有下游聚合（管线总览、月报、风险）自动跟随。

5

删除保护

Program / Project 存在引用时删除被拦截：接口返回 409 + 引用清单，前端弹出阻断说明并列出占用的 Study，引导先换绑或删除。无引用的实体（如 PRJ-NPC-1L）可正常删除。

6

快捷新建建的是实体

新增 Study 时可在表单内联快捷新建 Project：生成的是带全局唯一业务编码的独立实体（可被后续 Study 复用引用），而不是行内字符串。业务编码保存时由服务端分配，创建后不可修改。
