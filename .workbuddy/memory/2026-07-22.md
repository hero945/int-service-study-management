## 管线配置页维护方式拍板（产品决策）

- 背景：Program/Project 被多条 Study 共用，现状 `PipelineConfig` 为扁平行（program/project 为每行自由字符串），存在"编辑一行影响其他行"隐患。
- 决策：**实体分离 + 引用**。Program/Project 独立实体维护（业务编码不可改、BIGINT 主键关联），Study 表通过 projectCode 外键引用；行内禁止直接改共享实体名称，只能换绑。
- 接口：三张实体表 + 三组 CRUD（/api/config/programs|projects|studies）；重命名走 impact 预览 + 确认；删除有引用时 409 保护。
- 字段归属：Product/MOA/TA 上移至 Program/Project 级，PRD 4.1"同 Project 不同 Product 标记异常"规则随之退役。
- 交互：配置页 = Study 明细扁平表（默认）+ Program/Project 管理页签；Project 列下拉引用；允许表单内快捷新建 Project（建实体非字符串）；重命名弹窗明示影响 X Project / Y Study。
- Non-goals：改名审计、实体合并工具、TA 内拖拽规则不变。
- 待办（用户确认后）：更新 PRD 4.6 Markdown 并跑 docs/generate-prd-html.js；刷新 frontend/src/api/types.ts 的 PipelineConfig；PRD 附录补存量数据迁移规则（字符串去重 + 人工确认合并）。
