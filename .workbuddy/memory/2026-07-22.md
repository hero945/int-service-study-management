## 管线配置页维护方式拍板（产品决策）

- 背景：Program/Project 被多条 Study 共用，现状 `PipelineConfig` 为扁平行（program/project 为每行自由字符串），存在"编辑一行影响其他行"隐患。
- 决策：**实体分离 + 引用**。Program/Project 独立实体维护（业务编码不可改、BIGINT 主键关联），Study 表通过 projectCode 外键引用；行内禁止直接改共享实体名称，只能换绑。
- 接口：三张实体表 + 三组 CRUD（/api/config/programs|projects|studies）；重命名走 impact 预览 + 确认；删除有引用时 409 保护。
- 字段归属：Product/MOA/TA 上移至 Program/Project 级，PRD 4.1"同 Project 不同 Product 标记异常"规则随之退役。
- 交互：配置页 = Study 明细扁平表（默认）+ Program/Project 管理页签；Project 列下拉引用；允许表单内快捷新建 Project（建实体非字符串）；重命名弹窗明示影响 X Project / Y Study。
- Non-goals：改名审计、实体合并工具、TA 内拖拽规则不变。
- 待办（用户确认后）：更新 PRD 4.6 Markdown 并跑 docs/generate-prd-html.js；刷新 frontend/src/api/types.ts 的 PipelineConfig；PRD 附录补存量数据迁移规则（字符串去重 + 人工确认合并）。

## 里程碑页"只读"根因与修复

- 现象：`MilestoneView.vue` 始终显示"只读"，无法编辑（`canEdit = permissions.includes('milestone.update')` 为 false）。
- 根因：新增的权限点 `milestone.update` **从未播种**——前端 mock 演示账号权限列表缺它；后端 `hd_plt_permission` 从未注册该权限、也没授权给任何角色，导致真后端连管理员调 `PUT /milestones/:code` 都会 403。对照 `risk.update`（V10 迁移已播种并授权 ADMIN/USER）即知漏了这一步。
- 修复：
  - 新增 `db/migration/mysql/V11__milestone_permissions.sql` 与 `h2/V11__milestone_permissions.sql`：注册 `milestone.update`，授权 ADMIN + USER（VIEWER 保持只读，同 risk 策略）。
  - `frontend/src/api/mock.ts`：演示账号权限补 `'milestone.update'`，并在权限目录数组登记该条目。
- 验证：前端 12/12 + 构建成功 + Vue 架构 10/10；Maven 测试 V11 迁移已在 H2 成功应用（now at version v11）。仅 `TeamMatrixIntegrationTest` 6 个失败（pre-existing `program_name` 列缺失，与本次无关）。
- 教训：**新增带 `@PreAuthorize` 权限闸门的接口，必须同步写权限播种迁移（mysql + h2）并授权给角色，否则该接口在生产环境永远 403 / 前端永远只读。**
- 修复 `Unknown column 'action' in 'field list'`：根因是 `JdbcMilestoneRepository.audit()` 的审计 INSERT 自造了不存在的列名（`action`/`table_name`/`record_id`/`record_identifier`/`changed_by`/`changed_time`/`detail`）。改为真实列 `operator_user_id, operator_email, action_code, target_table, target_id, operation_reason, result_code`（参照 `JdbcRiskRepository.audit()`）。
- 新增 `study-management-test/.../MilestoneRepositoryIntegrationTest.java`：直插 study 后调用 `StudyMilestonePort.save()`，断言里程碑行入库 + 审计行写入真实列。已通过（Tests run:1, Failures:0, Errors:0）。
- 调试发现 H2 `V9__remove_pipeline_entity_names.sql` 删掉了 `study_name`/`program_name_snapshot`/`project_name_snapshot`/`project_name`/`program_name`，故测试 seed 必须避开这些列（MySQL 真实 schema 仍有）。`TeamMatrixIntegrationTest` 6 失败即此预存问题，非本次引入。
- 修复 `getKey() ... The current key entry contains multiple keys`：根因是 `JdbcMilestoneRepository.save()` 在 `INSERT ... ON DUPLICATE KEY UPDATE` 上用了 `GeneratedKeyHolder`+`key.getKey()`，MySQL 驱动对插入/更新两个分支都回传生成键。改为 upsert 后用 `SELECT id ... WHERE (study_id, milestone_code)` 回查 id（两列均有唯一约束）。移除 `PreparedStatement`/`GeneratedKeyHolder` 两个 import。
- 测试 `MilestoneRepositoryIntegrationTest` 新增第二次同节点 save，覆盖 `ON DUPLICATE KEY UPDATE` 更新分支（断言仍为 1 行、deviation_note 更新、2 条审计）。
