## 月报后端 MySQL 报错修复（DISTINCT + ORDER BY）

- 现象：真实 MySQL 报 `ORDER BY ... not in SELECT list ... incompatible with DISTINCT`，源在 `JdbcMonthlyReportRepository` 两处查询（`findAssignedFunctionLines` / `findStudyFunctionLines`）。
- 根因：两查询 `SELECT DISTINCT fl.id, fl.function_code, fl.function_name ... ORDER BY fl.sort_order`，`sort_order` 未进入 SELECT 列表，MySQL 在 DISTINCT 下禁止按非选中列排序（H2 宽松不报，属漏报）。
- 修复：两处 SELECT 均补 `fl.sort_order`（mapper 只读 id/code/name，多取一列无副作用），使该列既被选中又用于排序，对 H2 与 MySQL 均合法。
- 验证：clean 重编 + 跑 MonthlyReportIntegrationTest 5/5、PlatformIntegrationTest 9/9，BUILD SUCCESS。注意：本机只能跑 H2（MODE=MySQL），真实 MySQL 行为需另行连库验证；修复后 SQL 已符合标准，预期在真实 MySQL 同样通过。

## 管理员月报可见集修正（"admin 只看到部分进展"）

- 现象：admin 进入月报只看到部分功能线/进展。用户同时误判"两个插入没有事务"。
- 事务澄清：事务**存在**——`@Transactional` 在 `MonthlyReportManager` 的 `getMonthlyReports`/`createEntry`/`updateEntry`（`manager/MonthlyReportManager.java:40/70/93`）；`@SpringBootApplication` 自动装配 `DataSourceTransactionManager`；`BusinessException extends RuntimeException` 默认回滚。Repository 无 `@Transactional` 是架构设计（Manager 持有事务边界）。应填项 INSERT（GET 物化）与进展明细 INSERT（POST 写）分属**两次 HTTP 请求=两个独立事务**，属正常 REST 设计，非"无事务"。
- 真正 bug：`fillableLines` 管理员分支返回 `findStudyFunctionLines`（该 study 团队矩阵出现的功能线），仅空集才退回全部 ACTIVE——只要 study 有部分分配，admin 就被限成只看那几条，违背计划"管理员可填全部功能线"。
- 修复：`fillableLines` 管理员分支改为 `reports.findActiveFunctionLines()`（全部 ACTIVE 功能线），普通用户仍走 `findAssignedFunctionLines`。同步改正 `MonthlyReportIntegrationTest` 管理员断言（由固定 2 条改为断言等于库中 ACTIVE 功能线总数，动态查询）。测试库种了 17 条 ACTIVE 功能线。
- 验证：clean 重编跑 Monthly 5/5 + Platform 9/9，BUILD SUCCESS。
