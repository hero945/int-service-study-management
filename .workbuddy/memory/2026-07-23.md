## 月报后端 MySQL 报错修复（DISTINCT + ORDER BY）

- 现象：真实 MySQL 报 `ORDER BY ... not in SELECT list ... incompatible with DISTINCT`，源在 `JdbcMonthlyReportRepository` 两处查询（`findAssignedFunctionLines` / `findStudyFunctionLines`）。
- 根因：两查询 `SELECT DISTINCT fl.id, fl.function_code, fl.function_name ... ORDER BY fl.sort_order`，`sort_order` 未进入 SELECT 列表，MySQL 在 DISTINCT 下禁止按非选中列排序（H2 宽松不报，属漏报）。
- 修复：两处 SELECT 均补 `fl.sort_order`（mapper 只读 id/code/name，多取一列无副作用），使该列既被选中又用于排序，对 H2 与 MySQL 均合法。
- 验证：clean 重编 + 跑 MonthlyReportIntegrationTest 5/5、PlatformIntegrationTest 9/9，BUILD SUCCESS。注意：本机只能跑 H2（MODE=MySQL），真实 MySQL 行为需另行连库验证；修复后 SQL 已符合标准，预期在真实 MySQL 同样通过。

## V14 种子在真实 MySQL 报 Duplicate entry 'HDM1005'

- 现象：启动连真实 MySQL 时 Flyway 跑 V14 报 `Duplicate entry 'HDM1005' for key 'hd_plt_program.uk_hd_plt_program_product'`（Line 7 = Program INSERT）。
- 根因：V14 原写法假设目标库为空，但用户 MySQL 已含一条 `product_name='HDM1005'` 的 program（与种子同源，多半是早先手动/重复播种残留）；而 `hd_plt_program` 有 `UNIQUE KEY uk_hd_plt_program_product(product_name)`，`UNIQUE KEY uk_hd_plt_program_code(program_code)`，多行 INSERT 命中已存在约束即整句回滚。V14 自身 6 个 product_name 互不重复，故重复必来自库里既有数据。
- 修复：把 V14 三段 INSERT 全改为**幂等**写法 `INSERT ... ON DUPLICATE KEY UPDATE`（program 按 program_code/product_name、project 按 project_code、study 按 study_code 更新存活列），使迁移可重复运行、遇到同源数据不再报错。V9 已删 name 列故不引用。
- ⚠️ 注意：① 真实 MySQL 报错路径是 `target/classes/.../V14...`，即**编译副本**——必须 rebuild resources（`mvn clean` 或 IDE 重新 build）让修正版进入 classpath，否则 Flyway 仍跑旧的坏版本；Flyway 会把失败 V14 记为 FAILED 并在下次启动自动重试，无需手动 repair。② 若既有 HDM1005 的 program 其 `program_code` 不是 `PRG-MET-PEP`（即不同 code 同名产品），幂等更新会改到那行脏数据、且 study 子查询 `WHERE program_code='PRG-MET-PEP'` 找不到行而报 NOT NULL——此属真实数据冲突，需先 `DELETE FROM hd_plt_program WHERE product_name='HDM1005'` 或清整库演示数据再播种。诊断：`SELECT program_code, product_name FROM hd_plt_program WHERE product_name='HDM1005';`。
- 本机仅 H2，无法实跑真实 MySQL 验证；幂等写法为标准 Flyway 种子模式，预期在真实 MySQL 通过。
